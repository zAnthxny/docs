NovaRestore stores every configuration option in a single file that is generated automatically the first time the plugin loads. Understanding the layout of that file — and knowing which section controls which behaviour — makes day-to-day administration much easier. This page walks you through where the file lives, how to apply changes at runtime, and what each top-level section is responsible for.

## Config file location

NovaRestore writes its configuration to:

```text plugins/NovaRestore/config.yml
plugins/NovaRestore/config.yml
```

If the file does not exist when the server starts, the plugin copies a fully-commented default from inside the jar. You can edit any value in that file and reload it without restarting the server.

## Applying changes without a restart

Run the following command from the server console or as a player with the `rollback.reload` permission:

```bash in-game or console
/invrollback reload
```

This command re-reads `config.yml`, reconnects to the database if connection settings changed, and refreshes the Discord bot configuration. The alias `/invrestore reload` works identically.

<Note>
  If you change the Discord bot token you must restart the server rather than
  reload. The JVM argument that holds the token is only read during startup.
  See the [Discord page](/configuration/discord) for details.
</Note>

## Discord bot token

The bot token is **not** stored in `config.yml`. Pass it as a JVM argument when you start the server so it is never written to disk in plain text:

```bash server-start.sh
java -Ddiscord.token=YOUR_BOT_TOKEN_HERE -jar paper.jar
```

The `discord.bot-token` key in `config.yml` is intentionally left as a placeholder label. NovaRestore ignores it at runtime and reads only the JVM property.

## Minimal working config

The block below shows the smallest set of values you need to change before NovaRestore is production-ready on a single server. Everything else will use its built-in default.

```yaml config.yml
# Display name shown in Discord embeds and audit entries
server:
  name: "Survival-01"

# Language: "en" or "es"
lang: "en"

# Database — SQLite is the default; no extra changes needed for a single server
database:
  type: "SQLITE"

discord:
  # Channel where rollback request embeds are posted
  log-channel-id: "YOUR_CHANNEL_ID"

  # Role IDs that can approve or deny requests in Discord
  admin-role-ids:
    - "YOUR_STAFF_ROLE_ID"
```

<Tip>
  Pass the Discord bot token as a JVM argument so it is never stored on disk:
  `-Ddiscord.token=YOUR_TOKEN`. Do not put the real token inside `config.yml`.
</Tip>
