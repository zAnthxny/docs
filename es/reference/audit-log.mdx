NovaRestore mantiene un rastro de auditoría completo de cada acción que toca una instantánea de muerte. Desde el momento en que un miembro del staff envía una solicitud de restauración hasta la entrega final de ítems, cada paso se registra con una marca de tiempo, el actor responsable, y una nota descriptiva. Esto hace sencillo investigar disputas, confirmar qué se restauró y cuándo, y demostrarle a los jugadores exactamente qué sucedió con su solicitud.

<Tip>
Define `discord.audit-webhook-url` en tu configuración para que cada acción de auditoría se publique automáticamente a un canal de Discord dedicado. Esto le da a tu equipo de moderación un feed en vivo y buscable de toda la actividad de restauración sin necesitar nunca exportar archivos o ejecutar comandos.
</Tip>

## Qué se registra

El sistema de auditoría registra una entrada para cada evento significativo en el ciclo de vida de una instantánea:

| Acción | Se dispara cuando |
|---|---|
| `REQUEST` | Un miembro del staff envía una solicitud de restauración a Discord |
| `DENY` | Un admin de Discord deniega la solicitud |
| `CANCEL` | Un miembro del staff cancela una solicitud pendiente o en cola dentro del juego |
| `REOPEN` | Un miembro del staff reabre una instantánea denegada |
| `UNLOCK` | Un miembro del staff desbloquea una instantánea restaurada para permitir volver a solicitar |
| `TIMEOUT` | Una solicitud pendiente expira automáticamente (registrado por el sistema) |
| `RESTORE_*` | Los ítems se restauran inmediatamente (con sufijo del tipo de restauración, por ejemplo, `RESTORE_FULL`) |
| `DELIVER_*` | Una restauración en cola se aplica en el inicio de sesión del jugador (por ejemplo, `DELIVER_INVENTORY`) |
| `QUEUE_*` | Una restauración se aprueba y se pone en cola para entrega sin conexión (por ejemplo, `QUEUE_ARMOR`) |

## Campos de entrada del registro de auditoría

Cada entrada en el registro de auditoría contiene los siguientes campos:

| Campo | Descripción |
|---|---|
| `timestamp` | Milisegundos de época Unix cuando ocurrió la acción |
| `action` | La cadena de tipo de acción (por ejemplo, `REQUEST`, `DENY`, `RESTORE_FULL`) |
| `actor` | El nombre de usuario del miembro del staff que realizó la acción, o `SYSTEM` para eventos automatizados como timeouts |
| `player_name` | El nombre de usuario dentro del juego del jugador al que pertenece esta instantánea |
| `player_uuid` | El UUID del jugador al que pertenece esta instantánea |
| `death_id` | El ID único de la instantánea de muerte a la que se relaciona esta entrada |
| `snapshot_date` | La fecha y hora formateada cuando la instantánea de muerte se registró originalmente |
| `state` | El estado de la instantánea en el momento en que se escribió la entrada |
| `location` | El mundo y coordenadas donde ocurrió la muerte |
| `server_name` | El nombre del servidor tal como se configuró en `server.name` |
| `note` | Una descripción legible por humanos o motivo para la acción |

## Viendo registros dentro del juego

Para ver la actividad de auditoría más reciente para un jugador específico, usa el subcomando `logs`:

```bash title="View audit logs for a player"
/invrollback logs <player>
```

Este comando muestra hasta **12 entradas**, mostrando la última acción registrada para cada ID de muerte distinto. Cada entrada incluye la fecha, tipo de acción, actor, estado actual, nombre del servidor, y la nota más reciente. Es útil para una revisión rápida de un vistazo durante una sesión de soporte.

**Permiso requerido:** `rollback.logs`

## Exportando el registro de auditoría

Para análisis más profundo o archivado, puedes exportar el registro de auditoría a un archivo. Las exportaciones se guardan dentro de la carpeta `exports/` dentro del directorio de datos del plugin.

### Exporta el registro de un solo jugador

```bash title="Export one player's audit log as YAML"
/invrollback export yml <player>
```

```bash title="Export one player's audit log as JSON"
/invrollback export json <player>
```

### Exporta el registro global

```bash title="Export the entire audit log as YAML"
/invrollback export yml
```

```bash title="Export the entire audit log as JSON"
/invrollback export json
```

El nombre del archivo de exportación incluye una marca de tiempo en formato `yyyyMMdd-HHmmss` así que múltiples exportaciones nunca se sobrescriben entre sí. Tanto `yml` como `json` incluyen todos los campos de entrada.

**Permiso requerido:** `rollback.export`

## Webhook de auditoría

Cuando `discord.audit-webhook-url` está definido a una URL de webhook de Discord válida, el plugin envía un embed a ese canal para cada acción registrada. El embed del webhook incluye el nombre del jugador, actor, ID de muerte, estado, nombre del servidor, ubicación, y nota. Puedes usar un canal privado separado para este webhook para mantener un rastro de auditoría en tiempo real visible solo para tu equipo de staff senior.

```yaml title="config.yml — audit webhook configuration"
discord:
  audit-webhook-url: "https://discord.com/api/webhooks/YOUR_WEBHOOK_URL"
  audit-webhook-username: "NovaRestore Audit"
  audit-webhook-avatar-url: ""
```

## Política de retención

Las entradas del registro de auditoría se purgan automáticamente basándose en el ajuste `storage.retention.max-audit-age-days`. El predeterminado es 90 días. Define en `0` para desactivar la purga automática y mantener entradas indefinidamente.

```yaml title="config.yml — audit retention"
storage:
  retention:
    max-audit-age-days: 90
```

La purga se ejecuta al arranque del plugin y en el ciclo de mantenimiento programado. Un mensaje se registra a la consola cada vez que se eliminan entradas, así que siempre sabes cuándo se ejecutó la limpieza y cuántas filas se eliminaron.
