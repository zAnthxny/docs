---

Cada instantánea de muerte en NovaRestore tiene un estado que describe exactamente dónde está en el ciclo de vida de restauración. Los estados controlan qué acciones están disponibles para una instantánea, si cuenta contra el límite de solicitudes pendientes de un jugador, y si puede solicitarse de nuevo. Entender el modelo de estado ayuda al staff a gestionar restauraciones de inventario eficientemente y ayuda a los jugadores a saber qué esperar.

<Tip>
La GUI del navegador de instantáneas tiene un **botón de filtro** en la fila inferior. Úsalo para cambiar rápidamente entre vistas — por ejemplo, filtra por `pending` para ver solo instantáneas con solicitudes de Discord activas, o `queued` para verificar quién tiene restauraciones aprobadas esperando entrega.
</Tip>

## Los cinco estados de instantáneas

| Estado | Color | Significado |
|---|---|---|
| **Open** | 🟢 Verde | Instantánea guardada, ninguna solicitud enviada todavía. Completamente disponible. |
| **Pending** | 🟡 Amarillo | Una solicitud de restauración se ha enviado a Discord y está esperando revisión del staff. |
| **Queued** | 🔵 Cian | Solicitud aprobada pero el jugador estaba desconectado. Los ítems se entregarán en el próximo inicio de sesión. |
| **Restored** | 🟩 Verde oscuro | Ítems restaurados exitosamente. La entrada está bloqueada — no puede solicitarse de nuevo. |
| **Denied** | 🔴 Rojo | La solicitud fue denegada por el staff. Puede reabrirse con el permiso correcto. |

### Open

`OPEN` es el estado predeterminado para cada instantánea recién capturada. Significa que la muerte fue registrada y los datos están intactos, pero ninguna acción de restauración se ha iniciado. El staff puede abrir el menú de inspección para la instantánea, revisar los ítems, y enviar una solicitud a Discord. Una instantánea `OPEN` **no** cuenta contra el límite de solicitudes pendientes del jugador.

### Pending

`PENDING` significa que una solicitud de restauración se ha enviado y está activa en el canal de Discord, esperando que un admin la apruebe o deniegue. Una instantánea permanece en este estado hasta que alguien actúa sobre ella en Discord, se cancela vía `/invrollback cancel`, o expira (controlado por `requests.timeout-minutes` en la configuración). Las instantáneas pendientes **cuentan contra** el límite `requests.max-pending-per-player` del jugador.

### Queued

`QUEUED` es un estado transicional que ocurre cuando un admin de Discord aprueba una restauración pero el jugador objetivo está desconectado en ese momento. El plugin almacena el tipo de restauración aprobado junto a la instantánea y espera. Tan pronto como el jugador inicia sesión, los ítems se entregan automáticamente y la instantánea avanza a `RESTORED`.

### Restored

`RESTORED` es el estado terminal de éxito. Significa que los ítems se aplicaron al inventario del jugador (o se entregaron desde la cola). Una vez que una instantánea alcanza este estado está **bloqueada** — el menú de inspección la muestra como ya restaurada y el botón de solicitud está deshabilitado. Esto previene que la misma muerte se restaure dos veces.

Para permitir una segunda restauración en la misma muerte (por ejemplo, si solo parte de los ítems se devolvieron la primera vez), un miembro del staff con el permiso `rollback.manage.unlock` debe ejecutar:

```bash title="Unlock a restored snapshot"
/invrollback unlock <deathId>
```

Esto mueve la instantánea de vuelta a `OPEN` y registra la acción de desbloqueo en el rastro de auditoría.

### Denied

`DENIED` significa que un admin de Discord revisó la solicitud y la rechazó. El jugador recibe una notificación dentro del juego si `notifications.notify-target-player` está habilitado. Una instantánea denegada puede **reabrirse** por un miembro del staff con el permiso `rollback.manage.reopen` usando:

```bash title="Reopen a denied snapshot"
/invrollback reopen <deathId>
```

Reabrir una instantánea la devuelve a `OPEN` para que una nueva solicitud pueda enviarse.

## Diagrama de transición de estados

El siguiente diagrama muestra cada transición de estado válida:

```
[Death occurs]
      │
      ▼
    OPEN ◄──────────────────────────── (unlocked by staff)
      │                                        ▲
      │ (request submitted to Discord)         │
      ▼                                        │
   PENDING ──── (timed out / cancelled) ──► OPEN
      │
      ├─── (denied by staff) ──────────────► DENIED
      │                                        │
      │                                        └─ (reopened by staff) ──► OPEN
      │
      ├─── (approved, player online) ─────► RESTORED ◄─ (queued delivery applied)
      │
      └─── (approved, player offline) ───► QUEUED
                                              │
                                              └─ (player logs in) ──────► RESTORED
```

La única forma de salir de `RESTORED` es un desbloqueo manual de staff. La única forma de salir de `DENIED` es una reapertura de staff. Cualquier otra transición sucede automáticamente como parte del flujo de trabajo normal.
