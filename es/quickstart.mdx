Una vez que NovaRestore está instalado y tu servidor ha iniciado al menos una vez, ya tienes un `config.yml` funcional y una base de datos SQLite local lista. Esta guía te lleva por la configuración restante — conectar tu bot de Discord, asignar permisos y procesar una solicitud de restauración real — para que tu staff pueda empezar a aprobar restauraciones de inmediato.

<Note>
  Esta guía asume que ya completaste los pasos de [Instalación](/es/installation) y que el banner ASCII de NovaRestore apareció en tu consola sin errores.
</Note>

## Pasos de configuración

<Steps>
  <Step title="Abre config.yml">
    Navega a `plugins/NovaRestore/` en tu servidor y abre `config.yml` en un editor de texto. Este archivo se generó automáticamente en el primer inicio y contiene todas las opciones configurables de NovaRestore con comentarios explicativos.

    ```text filesystem
    plugins/
    └── NovaRestore/
        ├── config.yml      ← abre este archivo
        ├── data.db
        └── messages.yml
    ```
  </Step>

  <Step title="Define el nombre de tu servidor">
    Busca la sección `server` cerca de la parte superior de `config.yml` y define `name` con el nombre que quieres que aparezca en los embeds de Discord. Este valor es puramente cosmético — identifica de qué servidor proviene una solicitud de restauración dentro del canal de Discord.

    ```yaml config.yml
    server:
      name: "My Server"
    ```

    Elige un nombre que sea significativo para tu staff. Si ejecutas varios servidores que apuntan al mismo canal de Discord, cada uno debe tener un nombre único aquí para que las solicitudes sean fáciles de distinguir.
  </Step>

  <Step title="Pasa el token del bot de Discord como argumento de la JVM">
    NovaRestore requiere un token de bot de Discord para publicar embeds y recibir interacciones de botones. En lugar de guardar el token en `config.yml`, lo proporcionas como argumento de inicio de la JVM. Esto mantiene el token fuera de tu archivo de configuración y lejos de una exposición accidental en capturas de pantalla, copias de seguridad o el control de versiones.

    Agrega el siguiente argumento a tu comando de inicio del servidor:

    ```bash startup-command.sh
    java -Ddiscord.token=YOUR_BOT_TOKEN -jar paper-1.21.4.jar nogui
    ```

    Reemplaza `YOUR_BOT_TOKEN` con el token real de tu aplicación en el Discord Developer Portal. Si usas un script de inicio o un panel de gestión de servidor, agrega la bandera `-D` en el mismo lugar que tus otros argumentos de JVM (antes de `-jar`).

    <Tip>
      Guarda el token de tu bot en un gestor de secretos seguro o una variable de entorno en lugar de escribirlo directamente en un script de shell que podría subirse a un repositorio. Muchos paneles de despliegue permiten inyectar argumentos de JVM desde variables de entorno — revisa la documentación de tu proveedor para la sintaxis exacta.
    </Tip>

    El bot necesita los siguientes permisos de Discord para funcionar:
    - **Enviar mensajes** e **Insertar enlaces** en el canal de registro
    - **Leer historial de mensajes** en el canal de registro
    - Los alcances OAuth2 **bot** y **applications.commands** al generar la URL de invitación
  </Step>

  <Step title="Define el ID del canal de registro de Discord">
    De vuelta en `config.yml`, define `discord.log-channel-id` con el ID del canal de Discord donde deben aparecer los embeds de solicitudes de restauración. Para copiar el ID de un canal en Discord, activa el Modo Desarrollador en tu configuración de Discord, luego haz clic derecho en el canal y selecciona **Copiar ID de canal**.

    ```yaml config.yml
    server:
      name: "My Server"

    discord:
      log-channel-id: "123456789012345678"
    ```

    Guarda el archivo. Este cambio surte efecto en el próximo reinicio del servidor (o después de ejecutar `/invrollback reload` para aplicar cambios sin un reinicio completo).

    <Warning>
      El ID del canal debe estar entre comillas en YAML. Las cadenas numéricas sin comillas de más de 15 dígitos pueden interpretarse como un número de punto flotante y truncarse, lo que provocará que las llamadas a la API de Discord fallen silenciosamente.
    </Warning>
  </Step>

  <Step title="Asigna permisos al staff y a los jugadores">
    NovaRestore usa dos permisos principales. Asígnalos usando el plugin de permisos de tu servidor (LuckPerms, PermissionsEx, o equivalente).

    | Permiso | Quién lo necesita | Qué permite |
    |---|---|---|
    | `rollback.view` | Miembros del staff | Abrir la GUI de instantáneas de muerte dentro del juego y enviar solicitudes de restauración |
    | `rollback.request` | Jugadores | Enviar su propia solicitud de restauración desde la pantalla de muerte sin intervención del staff |

    **Ejemplos con LuckPerms:**

    ```text luckperms-commands
    # Otorga a un grupo de staff la capacidad de abrir y usar la GUI de restauración
    /lp group staff permission set rollback.view true

    # Otorga a todos los jugadores la capacidad de solicitar su propia restauración
    /lp group default permission set rollback.request true
    ```

    Reinicia el servidor (o usa `/lp editor` para aplicar cambios) antes de continuar.
  </Step>

  <Step title="Prueba: dispara una instantánea de muerte">
    Con los permisos en su lugar, provoca una muerte de prueba para crear una instantánea con la que trabajar. La forma más sencilla es cambiar una cuenta de prueba (o la tuya propia) a modo creativo, quitarle la armadura y causar suficiente daño para matarla en modo supervivencia — o simplemente usar `/kill <playerName>` en la consola.

    ```text console-command
    /kill TestPlayer
    ```

    NovaRestore captura la instantánea en el momento de la muerte. Deberías ver una confirmación en la consola:

    ```text console
    [NovaRestore] Snapshot saved for TestPlayer (death #1) at world,100,64,-200
    ```
  </Step>

  <Step title="Abre la GUI y envía una solicitud de restauración">
    Ahora abre la GUI de restauración de staff ejecutando el siguiente comando como operador o como jugador con `rollback.view`:

    ```text in-game-command
    /invrollback TestPlayer
    ```

    Se abre una GUI de cofre mostrando todas las instantáneas de muerte registradas para `TestPlayer`, ordenadas de más reciente a más antigua. Haz clic en la instantánea que acabas de crear. Se te pedirá introducir un motivo para la restauración — escribe algo como `Testing the workflow` y confirma.

    NovaRestore publica un embed de Discord en tu canal de registro configurado. El embed contiene:
    - El nombre del jugador y la ubicación de la muerte
    - La marca de tiempo de la muerte
    - Una vista previa de los ítems en la instantánea
    - El motivo que ingresaste
    - Botones de **Aprobar** y **Denegar**

    Haz clic en **Aprobar** en Discord. El bot de NovaRestore recibe la interacción, restaura el inventario a `TestPlayer` (de inmediato si está en línea), y actualiza el embed para mostrar el estado aprobado con tu nombre de usuario de Discord como revisor.

    <Info>
      Si el embed de Discord no aparece en unos segundos, verifica que el bot esté en línea en tu servidor de Discord, que el `log-channel-id` sea correcto, y que el bot tenga permiso para enviar mensajes en ese canal.
    </Info>
  </Step>
</Steps>

## Referencia de configuración mínima

El siguiente bloque muestra los valores mínimos de `config.yml` que necesitas definir antes de que la integración con Discord de NovaRestore esté operativa. Todas las demás opciones son opcionales y están documentadas en la página de [Configuración](/es/configuration/overview).

```yaml config.yml
server:
  name: "My Server"

discord:
  log-channel-id: "123456789012345678"
```

<Note>
  Esta configuración mínima depende de que todos los demás ajustes estén en sus valores predeterminados: base de datos SQLite, mensajes en inglés y diseño de GUI estándar. Consulta la [Referencia de configuración](/es/configuration/overview) completa para ver todas las opciones disponibles, incluyendo configuración de MySQL, personalización de mensajes y políticas de retención de instantáneas.
</Note>
