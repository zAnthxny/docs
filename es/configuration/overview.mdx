NovaRestore guarda todas las opciones de configuración en un único archivo que se genera automáticamente la primera vez que el plugin se carga. Entender la estructura de ese archivo — y saber qué sección controla qué comportamiento — hace que la administración diaria sea mucho más fácil. Esta página te guía por dónde vive el archivo, cómo aplicar cambios en tiempo real y de qué es responsable cada sección de nivel superior.

## Ubicación del archivo de configuración

NovaRestore escribe su configuración en:

```text plugins/NovaRestore/config.yml
plugins/NovaRestore/config.yml
```

Si el archivo no existe cuando el servidor inicia, el plugin copia un valor predeterminado totalmente comentado desde dentro del jar. Puedes editar cualquier valor en ese archivo y recargarlo sin reiniciar el servidor.

## Aplicar cambios sin reiniciar

Ejecuta el siguiente comando desde la consola del servidor o como un jugador con el permiso `rollback.reload`:

```bash in-game or console
/invrollback reload
```

Este comando vuelve a leer `config.yml`, se reconecta a la base de datos si cambiaron los ajustes de conexión, y actualiza la configuración del bot de Discord. El alias `/invrestore reload` funciona de manera idéntica.

<Note>
  Si cambias el token del bot de Discord debes reiniciar el servidor en lugar
  de recargar. El argumento de la JVM que contiene el token solo se lee durante el inicio.
  Consulta la [página de Discord](/es/configuration/discord) para más detalles.
</Note>

## Token del bot de Discord

El token del bot **no** se guarda en `config.yml`. Pásalo como argumento de la JVM al iniciar el servidor para que nunca se escriba en disco en texto plano:

```bash server-start.sh
java -Ddiscord.token=YOUR_BOT_TOKEN_HERE -jar paper.jar
```

La clave `discord.bot-token` en `config.yml` se deja intencionalmente como una etiqueta de marcador de posición. NovaRestore la ignora en tiempo de ejecución y solo lee la propiedad de la JVM.

## Configuración mínima funcional

El bloque a continuación muestra el conjunto más pequeño de valores que necesitas cambiar antes de que NovaRestore esté listo para producción en un solo servidor. Todo lo demás usará su valor predeterminado incorporado.

```yaml config.yml
# Nombre visible mostrado en los embeds de Discord y las entradas de auditoría
server:
  name: "Survival-01"

# Idioma: "en" o "es"
lang: "en"

# Base de datos — SQLite es el predeterminado; no se necesitan cambios adicionales para un solo servidor
database:
  type: "SQLITE"

discord:
  # Canal donde se publican los embeds de solicitudes de restauración
  log-channel-id: "YOUR_CHANNEL_ID"

  # IDs de rol que pueden aprobar o denegar solicitudes en Discord
  admin-role-ids:
    - "YOUR_STAFF_ROLE_ID"
```

<Tip>
  Pasa el token del bot de Discord como argumento de la JVM para que nunca se guarde en disco:
  `-Ddiscord.token=YOUR_TOKEN`. No coloques el token real dentro de `config.yml`.
</Tip>
