NovaRestore almacena cada opción de configuración en un único archivo que se genera automáticamente la primera vez que el plugin carga. Entender el diseño de ese archivo — y saber qué sección controla qué comportamiento — hace que la administración diaria sea mucho más fácil. Esta página te guía a través de dónde vive el archivo, cómo aplicar cambios en tiempo de ejecución, y de qué es responsable cada sección de nivel superior.

## Ubicación del archivo de configuración

NovaRestore escribe su configuración en:

```text plugins/NovaRestore/config.yml
plugins/NovaRestore/config.yml
```

Si el archivo no existe cuando el servidor arranca, el plugin copia un valor predeterminado completamente comentado desde dentro del jar. Puedes editar cualquier valor en ese archivo y recargarlo sin reiniciar el servidor.

## Aplicando cambios sin un reinicio

Ejecuta el siguiente comando desde la consola del servidor o como un jugador con el permiso `rollback.reload`:

```bash in-game or console
/invrollback reload
```

Este comando vuelve a leer `config.yml`, se reconecta a la base de datos si los ajustes de conexión cambiaron, y refresca la configuración del bot de Discord. El alias `/invrestore reload` funciona de manera idéntica.

<Note>
  Si cambias el token del bot de Discord debes reiniciar el servidor en lugar de
  recargar. El argumento de JVM que contiene el token solo se lee durante el arranque.
  Consulta la [página de Discord](/es/configuration/discord) para detalles.
</Note>

## Token del bot de Discord

El token del bot **no** se almacena en `config.yml`. Pásalo como un argumento de JVM cuando inicias el servidor para que nunca se escriba en disco en texto plano:

```bash server-start.sh
java -Ddiscord.token=YOUR_BOT_TOKEN_HERE -jar paper.jar
```

La clave `discord.bot-token` en `config.yml` se deja intencionalmente como una etiqueta de marcador de posición. NovaRestore la ignora en tiempo de ejecución y solo lee la propiedad de JVM.

## Configuración mínima funcional

El bloque a continuación muestra el conjunto más pequeño de valores que necesitas cambiar antes de que NovaRestore esté listo para producción en un solo servidor. Todo lo demás usará su valor predeterminado incorporado.

```yaml config.yml
# Display name shown in Discord embeds and audit entries
server:
  name: "Survival-01"

# Language: "en" or "es"
lang: "en"

# Database — SQLite is the default; no extra changes needed for a single server
database:
  type: "SQLITE"

discord:
  # Channel where rollback request embeds are posted
  log-channel-id: "YOUR_CHANNEL_ID"

  # Role IDs that can approve or deny requests in Discord
  admin-role-ids:
    - "YOUR_STAFF_ROLE_ID"
```

<Tip>
  Pasa el token del bot de Discord como un argumento de JVM para que nunca se almacene en disco:
  `-Ddiscord.token=YOUR_TOKEN`. No pongas el token real dentro de `config.yml`.
</Tip>
