NovaRestore se distribuye con diez nodos de permiso granulares para que puedas adaptar exactamente qué funciones puede acceder cada nivel de staff y tu base de jugadores. Ningún permiso se otorga por defecto — debes asignarlos explícitamente a través de tu plugin de permisos. El nodo comodín `rollback.admin.all` está disponible cuando quieres otorgar acceso irrestricto a un rol de confianza.

<Note>
  Los permisos se evalúan usando el sistema de permisos estándar de Bukkit. Cualquier plugin de permisos que se integre con Bukkit (LuckPerms, PermissionsEx, PowerRanks, etc.) es totalmente compatible.
</Note>

## Todos los nodos de permiso

| Nodo | Quién debería tenerlo | Descripción |
|---|---|---|
| `rollback.view` | Staff (todos los niveles) | Abre la GUI del navegador de instantáneas para cualquier jugador. Requerido para usar `/invrollback <player>`. |
| `rollback.request` | Jugadores, Staff | Envía una solicitud de restauración de inventario desde el menú de inspección. Sin este nodo, el botón de solicitud está inactivo. |
| `rollback.info` | Staff (todos los niveles) | Ver estadísticas de instantáneas (`info`/`stats`) e historial reciente (`history`) para cualquier jugador. |
| `rollback.logs` | Senior Staff, Moderator+ | Ver las últimas 12 entradas del registro de auditoría para un jugador vía `/invrollback logs`. |
| `rollback.manage.cancel` | Moderator+ | Cancela una solicitud de restauración pendiente por ID de muerte con un motivo requerido. |
| `rollback.manage.reopen` | Moderator+ | Reabre una solicitud denegada, moviéndola de vuelta al estado OPEN. |
| `rollback.manage.unlock` | Moderator+ | Desbloquea una entrada de muerte RESTORED para permitir que se procese de nuevo. |
| `rollback.export` | Admin+ | Exporta datos del registro de auditoría a archivos YAML o JSON. |
| `rollback.reload` | Admin+ | Recarga `config.yml` y reinicia la conexión del bot de Discord. |
| `rollback.admin.all` | Owner, Admin | Comodín que otorga **todos** los nodos anteriores simultáneamente. |

## Configuraciones de rol recomendadas

La tabla a continuación mapea los cuatro roles de servidor más comunes a los permisos que típicamente necesitan. Ajusta estos para que se ajusten a tu propia jerarquía.

| Rol | Permisos recomendados |
|---|---|
| **Owner / Admin** | `rollback.admin.all` |
| **Moderator** | `rollback.view`, `rollback.info`, `rollback.logs`, `rollback.manage.cancel`, `rollback.manage.reopen`, `rollback.manage.unlock` |
| **Helper** | `rollback.view`, `rollback.info` |
| **Player** | `rollback.request` |

---

## Ejemplo de configuración de LuckPerms

Los fragmentos a continuación muestran cómo aplicar estos roles usando comandos de LuckPerms o el formato `config.yml`. Adapta los nombres de grupo para que coincidan con tu servidor.

<Tabs>
  <Tab title="Comandos de LuckPerms">
    ```bash title="Owner / Admin group"
    /lp group admin permission set rollback.admin.all true
    ```

    ```bash title="Moderator group"
    /lp group moderator permission set rollback.view true
    /lp group moderator permission set rollback.info true
    /lp group moderator permission set rollback.logs true
    /lp group moderator permission set rollback.manage.cancel true
    /lp group moderator permission set rollback.manage.reopen true
    /lp group moderator permission set rollback.manage.unlock true
    ```

    ```bash title="Helper group"
    /lp group helper permission set rollback.view true
    /lp group helper permission set rollback.info true
    ```

    ```bash title="Player / default group"
    /lp group default permission set rollback.request true
    ```
  </Tab>
  <Tab title="YAML (estilo groups.yml)">
    ```yaml title="LuckPerms groups.yml excerpt"
    groups:
      admin:
        permissions:
          - rollback.admin.all

      moderator:
        permissions:
          - rollback.view
          - rollback.info
          - rollback.logs
          - rollback.manage.cancel
          - rollback.manage.reopen
          - rollback.manage.unlock

      helper:
        permissions:
          - rollback.view
          - rollback.info

      default:
        permissions:
          - rollback.request
    ```
  </Tab>
</Tabs>

## Notas de herencia de permisos

<AccordionGroup>
  <Accordion title="¿rollback.admin.all también cubre rollback.request?">
    Sí. `rollback.admin.all` está declarado como un padre en `plugin.yml` e incluye explícitamente `rollback.request`. Los admins pueden enviar solicitudes desde el menú de inspección tal como los jugadores regulares pueden.
  </Accordion>
  <Accordion title="¿Qué sucede si un jugador no tiene permisos en absoluto?">
    Ejecutar `/invrollback` sin ningún permiso coincidente muestra un mensaje de "no permission" y nada se revela sobre los subcomandos disponibles. Ningún nodo de permiso es predeterminado en `true`, así que tus jugadores comienzan con una pizarra limpia.
  </Accordion>
  <Accordion title="¿Puedo otorgar solo el comodín y omitir los nodos individuales?">
    Sí. Asignar `rollback.admin.all` a un grupo es totalmente equivalente a asignar los nueve nodos individuales. No necesitas listarlos por separado a menos que quieras mezclar y combinar — por ejemplo, otorgando `rollback.admin.all` pero luego negando explícitamente `rollback.reload` para un admin semi-confiable.
  </Accordion>
</AccordionGroup>
